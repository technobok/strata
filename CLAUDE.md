# Claude Code Instructions

## Build/Run Commands
```bash
make sync                # Install dependencies (local dev)
make init-db             # Create / migrate the local dev DB
make rundev              # Run dev server
make check               # lint + test — run before every commit
make lint                # ruff format + ruff check + ty check
make test                # pytest suite (tests/; fresh DB + DATA_ROOT per test)
make config-list         # Show config
make config-set KEY=key VAL=value  # Set config
strata-admin reconcile --dry-run   # Retention + orphaned-file sweep (drop --dry-run to apply)

# Docker (deployment)
docker compose build && docker compose up -d   # both containers migrate on start (race-safe)
make rebuild             # Rebuild images + apply DB migrations
make db-init             # Apply DB migrations only (no rebuild, no restart)
```

## Architecture
- Backend: Python Flask + APSW (SQLite metadata) + DuckDB (build + query engine). `pytz` is required (DuckDB needs it to fetch TIMESTAMPTZ results).
- Frontend: HTMX + PicoCSS (compact styling) + dark/light mode + vendored CodeMirror (attaches to `textarea.sql-editor`).
- Core object: a **datamodule** — a versioned DuckDB database built by a script, stored under `DATA_ROOT/<uuid[:2]>/<uuid>/{versions,sources,tmp}/` (dev default `instance/data`). "Live" is a SQLite pointer (`datamodule.live_version_id`) to an immutable snapshot; rebuilds atomic-swap a new file (TTL pull, single-flight via a cross-process lease on the datamodule row: `BuildLease` in `datamodule_service`). Retention prunes old versions (rows AND files) after each build; `strata-admin reconcile` sweeps the rest.
- Build inputs: uploaded source files (`source('name')` in scripts), dependencies (other datamodules ATTACHed by local name, TTL-pulled, cycle-rejected), and `connection`-table databases via `connection_service.attach_into`.
- **The serve path never builds**: a signed-in non-viewer gets 403 before anything that could start a build (html: `forbid`; data: plain 403); keyed requests are not membership-checked. `reports.serve` then resolves the version via `build_queue.servable_version` (fresh → serve; stale → coalesced unforced `stale-read` job + bounded wait `serve.max_wait_seconds` → else serve the last good version marked stale; failure backoff `consecutive_failures`/`retry_after`). `report_service.run_table/stream` take the version to serve and never build.
- Reports are DuckDB **macros** layered on a datamodule, served over the live version at `/r/<uuid>.<ext>` (html/parquet/csv/json/xlsx). Bodies use `$arg` for macro parameters (internally prefixed `arg_`).
- Serve query grammar (`services/query_filter.py`): declared args by name; `col__op=value` filters (eq/ne/gt/gte/lt/lte/in/between/contains/isnull); bare `col=v`; `q=` all-column search; `sort=-a,b`; `page=N` (200/page); `version=<version_uuid>` pins a historical snapshot (never rebuilds). Fields are DESCRIBE-validated, values parameter-bound; unknown keys error. Reserved (rejected as arg names): sort, page, q, format, key, version.
- API keys: sha256-hashed bearer tokens (`?key=`, or an `Authorization: Bearer` header since 2026-11-24 — `reports._sent_token`; two different keys = 400; html never reads either) grant unauthenticated access to **data formats only** (html stays SSO); every keyed request is in the read audit. Two kinds: **admin keys** (made by owners on the datamodule page; since 2026-11-23 always the whole datamodule, no scope choice, and the token is kept Fernet-encrypted so the page's API keys table lists each key's per-report xlsx links any time; older keys may be report-scoped and hash-only until rotated; fixed args always win, optional whitelist restricts caller args) and **each datamodule's Excel link** (one per DATAMODULE since 2026-11-23, migration 0011: `api_key.datamodule_excel_link = 1`, scope 'datamodule', a partial unique index on `datamodule_id`; model attr `ApiKey.excel_link`). It is made the first time a viewer opens any of its reports' lazy "Use in Excel" `<details>` (`GET /r/<uuid>/excel`, HTMX, viewers only); every report's box shows it; the token is also Fernet-encrypted in `token_encrypted` (`strata/crypto.py`, keyed by the DB's own `secret_key`) so it can be shown again; replaced (`POST /r/<uuid>/excel/replace`, or Rotate on the datamodule page) only by the datamodule's owners and admins, which also DISABLES the reports' old per-report Excel links (0008 column `excel_link`, model attr `ApiKey.old_report_link`: they kept working after 0011). The link keeps the view's args/filters/sort/q, never `page`/`version`; xlsx is the box's default (Excel's From Web cannot open Parquet). The datamodule page's Reports table has each report's Excel link (Copy), made there for owners if missing. 0011 added a column instead of changing 0008's CHECK: a table rebuild would have cascade-deleted the old `api_key_access_log` (foreign keys are on; 0013 replaced that table with `read_log`). `/admin/keys` lists every key (read-only). Migration 0008 = two `ADD COLUMN`s (a column CHECK may reference other columns) + the index.
- Schema is migration-managed: `database/migrations/NNNN_*.sql` applied forward-only by `db.apply_migrations` (ledger `schema_migrations`, `EXPECTED_SCHEMA_VERSION`). Before the first migration of a file, under the write lock, it refuses (`UnusableDatabase`) a file that already holds tables: the pre-datamodule schema (`PREPIVOT_TABLES`) points at `strata-admin adopt-prepivot` (`src/strata/prepivot.py`: old file kept as `<name>.prepivot-<stamp>.sqlite3`, new DB keeps known settings + `secret_key` + connections); anything else is "Strata did not make it". Fixture: `tests/fixtures/prepivot_schema.sql`.
- Auth: Gatekeeper client (SSO). Mail: `services/notify_service` (Phase C2) sends scheduled runs through Outbox (`outbox.db_path`, or `outbox.url` + `outbox.api_key`), resolving recipients (usernames, `@groups`, emails) through `app.config["GATEKEEPER_CLIENT"]`; it never raises (outcome on `report_run.notify_note`). Tests inject `app.config["NOTIFY_SINK"]` (a callable) and a fake Gatekeeper. Report schedules are `schedule` rows with `action='email'` + `report_id` + per-schedule `recipients_json`/`parameters_json`; due ones queue `build_job` rows with `kind='run'` (coalescing is builds-only; one running job per datamodule covers both kinds).

## Key Patterns
- Tests drive the real routes through the Flask test client (`tests/conftest.py`): a fresh SQLite DB + DATA_ROOT per test, an injected admin user (`X-User: <name>` + optional `X-Groups: a,b` = a non-admin in those groups, built by `conftest.as_user(name, *groups)`; `X-User: viewer` = the plain non-admin; `X-Anon: 1` = anonymous), and the `strata` fixture's authoring helpers.
- App factory in `src/strata/__init__.py`
- APSW db module with Flask-context and standalone transactions in `src/strata/db.py`
- Typed config registry in `src/strata/config.py`. Each entry says when a change applies (`Applies`). `Applies.LIVE` settings (build.*, serve.*, schedule.*, runs.*, access.*, auth.writer_group, worker.poll_interval) are read at use with `config.live_str/int/bool/list` (app_setting, 5 s cache, dropped on every write in-process) and are NOT in `KEY_MAP`/app.config; the rest are loaded into app.config at `create_app`. Tests change settings with `strata.set_config({...})` (posts /admin/config), never by poking app.config.
- All models are dataclasses with static CRUD methods
- Blueprints in `src/strata/blueprints/`
- **Access** (`services/access.py`): admins (`auth.admin_group`) do everything; writers (`auth.writer_group`, live) also create datamodules. Lists of principals = usernames (ignoring case; Gatekeeper's look like `asiap\pawe`), `@groups`, `*` (everyone signed in); defaults `access.default_owners` (blank = `@<writer group>`) / `access.default_viewers` (`*`). `matches(g.user, list)` for a request; `Directory().missing(subjects, audience)` for rules over lists (admins are in every audience; decides from the lists alone when it can, asks Gatekeeper `get_group_members` otherwise; no answer raises `DirectoryUnavailable`, never a yes); `Directory().unknown(list)` finds names Gatekeeper does not know. Each datamodule has `owners`/`viewers` (`owners_json`/`viewers_json`, NULL = the defaults; migration 0009 pinned pre-AC datamodules to owners `[]` = admins only) and `access_lock`; `access.can_own(dm)` / `can_view(dm)` (also Jinja globals, with `is_writer`). `owner_required` (blueprints/auth) guards every route naming a datamodule, report, schedule or key (`access.datamodule_for(view_args)`); `writer_required` guards `/datamodules/new`; refusals are `forbid(message)` → 403 `forbidden.html`. The Access fieldset carries `access_present` (a ticked "use the default" box = NULL); the saver must stay an owner unless admin; `*` only views; unknown names are refused when Gatekeeper is configured. `tests/test_access_lists.py::test_every_authoring_route_is_for_owners` sweeps the url_map: **a new route under datamodules/schedules must be `owner_required` or be exempted there by name.** Readers (AC2): report pages + data, runs (`runs._load`), the Excel box and `/checks` need `can_view`; viewers rebuild from the report page (`POST /r/<uuid>/build`, plain build, back to the report; cascade stays on the owners' datamodule page); the dependency picker and `dependency_add` offer only datamodules the user can view (a refusal reads like "not found"); Edit / Save a run / the datamodule link show for owners only.
- Services in `src/strata/services/`
- **The dependency rule and the access lock** (AC4): each owner of a dependant must be an owner or viewer of each parent (`access.parent_problem`), checked when a dependency is added, when owners are saved, by the script preview, and at every build (`access.check_build`, with the connection rule). A build failing it, or getting no answer from Gatekeeper, raises `AccessError(dm.id, reason)`: `_build_leased`'s failure path sets `datamodule.access_lock` only when `exc.dm_id == dm.id` (a parent's lock or AccessError fails a dependant without locking it; `_resolve_dependencies` re-reads each parent after its refresh and refuses a locked one), mails `alert_service.access_locked` once when newly set (whatever started the build; it sets `failure_alerted_at`, so "recovered" follows), and the next successful build clears it. A locked datamodule serves NOTHING to anyone, admins and keys included: `reports.serve` checks before the freshness wait (a `?version=` pin skips it) and again after it (the stale-read build may have locked it), the Excel box, Build now, Run now, runs (`runs._load`) and `run_service.run` (a scheduled run becomes an error mailed to the alert list, no rows) all refuse. Owners and admins see the reason (it names people); others see `access.LOCKED`. Its datamodule page stays open to owners/admins with a banner; `/checks` health = "locked". Saving a parent's lists warns (not refuses) about dependants whose next build would lock.
- **Mail and access** (AC6): a datamodule is **restricted** when its effective viewers lack `*` (`access.is_restricted`); its run mail (`notify_service.build_run_mail`) carries the count, data-as-of and the run link, never rows (Outbox keeps bodies in a shared DB), and NO mail about it quotes an error text (`notify_service.quotes_errors` / `error_html` / `data_note_text`: run mail's "refresh failed" note, the failed-run mail, the build-failing and stale alerts) — a gate check's error lists sample rows and DuckDB quotes values. Recipients outside its owners/viewers still get mail; `access.recipients_outside(dm, entries)` names them (email addresses cannot be matched) on save (flash), on the schedule form (banner) and in the report's Schedules table (`schedule_rows(..., dm)`). The help page `docs/access.md` ("Access") covers roles, lists, connections, the dependency rule, locks, keys, restricted mail and a payroll recipe. Stage-gate smoke (real worker + gunicorn web + real Gatekeeper and Outbox DBs, gk_session cookies): `~/dev/claude/work/strata/smoke-ac/smoke.sh`.
- External DB connections live in the `connection` table, params encrypted with Fernet keyed off `app_setting.secret_key`. Each has a **"May use" list** (`connection.users_json`, migration 0010; NULL = the admins only): who may bind it (`access.may_use`; the picker and `connection_add` offer only those), and every owner of a datamodule must be on the list of each connection bound to it — checked when binding, when the owners are saved (`_inputs_allow`), and at every build (`access.check_build(dm)` at the top of `_build_leased`'s try, before any input is read or rebuilt; `AccessError` fails the build). Admins are in every audience, so a person not listed needs Gatekeeper to tell whether they are an admin: tests of these rules use the `gatekeeper` fixture (conftest; `mail` uses it too), and without one the check refuses ("access could not be checked"). A connection save warns (does not refuse) about bound datamodules whose owners are no longer allowed. `tests/test_connections.py::_new_connection` makes connections `@strata-writers` may use (the owners of a datamodule on the defaults). Adding a driver = registering a `DriverSpec` in `src/strata/services/connection_service.py:DRIVERS` (its `usage` is the line the datamodule page shows per binding). A build reads ONLY the connections bound to its datamodule, each by its local name: sqlite/postgres = an ATTACHed database `<local>`, ODBC = the session variable `<local>`, read through the TEMP macro `odbc('<local>', '…')` (`connection_service.ODBC_MACRO`, defined when an ODBC connection is attached; no prefix since 2026-11-23). **FreeTDS limits, measured 2026-11-24 on Debian tdsodbc 1.3.17 + DuckDB 1.5.6 vs SQL Server 2022 (scripts `~/dev/claude/scratch/strata-d2/`):** odbc_query's SQL Server defaults fail on EVERY decimal column (the macro passes `decimal_columns_precision_through_ard=FALSE, decimal_columns_as_chars=TRUE`: exact; `…as_ard_type=FALSE` instead returns WRONG numbers silently, so a script containing `decimal_columns_` is refused, `ODBC_OPTIONS_REFUSED`); a multi-statement T-SQL batch cannot be read (SQLPrepare sees 0 columns); one handle cannot be read twice in one DuckDB statement (per-company = CREATE TABLE then `INSERT INTO … BY NAME`). `datamodule_service._explain_build_error` adds a hint to each of those DuckDB errors, lists the bound ODBC names for a NULL handle, and REPLACES DuckDB's "INSTALL/LOAD odbc_scanner" advice with `NO_ODBC_BOUND` when nothing is bound.
- **Every DuckDB connection that runs author SQL goes through `services/duck.py`** (`serve_conn`, `lock_down_build`): trusted setup (ATTACH, extension LOAD) first, then `lock_down` (external access off, allowed directories, locked config). Never call `duckdb.connect` for author SQL directly. Report bodies/constraint queries must pass `duck.validate_select` (exactly one SELECT). `build.sandbox` (config) is the build-side escape hatch.
- **Builds run in `strata-worker`** (`src/strata/worker.py`): `build_queue.request_build` records a coalesced `build_job`; workers claim with one `UPDATE … RETURNING`. Tests and `strata-web --dev` set `WORKER_INLINE` so requested builds run synchronously in the caller (`tests/test_worker.py` turns it off to exercise the queue).
- **Schedules are RFC 5545 RRULEs** (`services/schedule_service.py`, python-dateutil): the builder form → `Definition` JSON (`kind`, `fields`, `timezone`, `rrule`, `dtstart`); the `rrule` kind is the escape hatch for new shapes (no code). `schedule_service.run_due` (the worker's tick) queues forced builds for datamodule schedules and `kind='run'` jobs for report schedules; `Schedule.claim_run` is a compare-and-set on `next_run_at`.
- **Checks and runs** (Phase C1): a check = a report + a `report_check` row (severity, `gate`). Gate checks run in `_build_leased` after the script, before CHECKPOINT, on the build connection with arg defaults (`report_service.gate_rows`); rows or an error raise `GateError` → normal build failure. A **run** (`services/run_service`, `report_run`) saves the report's rows as `DATA_ROOT/<fan>/<dm>/runs/<run uuid>.parquet` (COPY under `_exports` then rename: the serve sandbox is never widened); the run page reuses `reports/_table.html` via `reports.build_ui(url_fn, …)`. Web "Run now" resolves the version like the serve path (`version_for_web`, never builds); the worker uses `version_inline` (ensure_fresh in-thread, falls back to the last good version + `data_note`). `runs.retention_days` pruning lives in the worker sweep and `reconcile`.
- **Alerts** (Phase C3, `services/alert_service`): per-datamodule `alert_recipients` (NULL = `@<auth.admin_group>`), "build failing" once per run of failures (`failure_alerted_at`; never for `manual:` builds), "recovered" on the next success, "data is stale" once past `stale_alert_seconds` (worker sweep; `stale_alerted_at`, re-armed by a success). Hooks sit in `_build_leased`'s failure and success paths; alerts never raise, and the `*_alerted_at` marks are set only when a mail went out. The datamodule form's Alerts fieldset carries `alerts_present`, so a post without it (e.g. `strata.set_script`) leaves alerts alone.
- **Jinja build scripts** (Phase C4, `services/script_template`): a script containing `{{`/`{%` renders in Jinja's `SandboxedEnvironment` (StrictUndefined) after dependencies are resolved and before `source()` expansion; `rows(local_name, sql)` runs one SELECT on that dependency's version through `duck.serve_conn` (max 10,000 rows); filters `sqlstr`/`ident`. The version's `build_script_snapshot` is the rendered text. Errors raise `ScriptTemplateError("build script, line N: …")`. Preview: `POST /datamodules/<uuid>/preview-script` (live dependency versions). CodeMirror editors save to their textarea on every change.
- **In-app help** = `docs/*.md` rendered at `/help/<page>` (`blueprints/help.py`, mistune; `PAGES` lists them in sidebar order; `docs/design/` is history, not served). Templates link a section with `{{ help_link('page', 'anchor') }}` (GitHub-style heading anchors; pages link each other as `urls.md#filters`). `tests/test_help.py` fails when a help link or doc link points nowhere, or when an operator, reserved key, schedule kind, arg type/widget or setting is missing from its page: **a change to any of those updates the docs in the same commit.**
- **Home `/` = the Reports page** (AC5, `access.readable_reports`): every report the user can view, grouped by datamodule path, checks and locks marked; owners get a link into each datamodule, writers "New Datamodule". **Top nav by role**: Reports, Datamodules (`access.shows_datamodules()`: writers, admins, and anyone who owns one), Checks, Admin (admins), Help, user. Tags (admin-only, attached to nothing) are on the Admin page, not the nav.
- **Top nav = the pattern shared with the sibling apps** (outbox, gatekeeper, clara, budget, stocktake): `ul#nav-menu.nav-menu` behind a `.nav-toggle` hamburger at ≤767px (re-measured 2026-11-23 for AC5: at 768px the admin menu fits with `asiap\pawe` (114px spare) and with a 24-character username (13px spare); a viewer's needs ~390px; recipe `~/dev/claude/scratch/strata-ac/width2.py` + `serve.py`; Pico's container is 510px below 768px, 700px to 1023px), the username links to Gatekeeper's whoami page (`auth.whoami_url()`, where people sign out), no Logout link. CSS block at the end of `app.css`, handler at the end of `app.js`. A new nav item: re-measure the breakpoint.
- **Auth probe** (X0, `blueprints/diag.py` + `services/auth_probe.py`): `/diag/auth-probe.json`, no login, 404 unless the live setting `diag.auth_probe` is on. It reports what a request carried (header/cookie NAMES, the `Authorization` scheme, a bearer JWT's unverified header + listed claims) and never a token, signature or credential; `?challenge=<tenant>` answers a request without a token with Power Query's 401 + `WWW-Authenticate: Bearer authorization_uri=…`. Each answer is logged at INFO. Smoke on real gunicorn: `~/dev/claude/work/strata/smoke-x0/smoke.sh`.
- **Logging:** `strata.logs.configure()` (INFO to stderr) is called by strata-worker and by strata-web (in each gunicorn worker's `load()`, and `--dev`). Without it gunicorn drops every `strata.*` INFO line.
- **Buttons and links** (2026-11-24): `<a role="button">` goes somewhere (GET: Edit, Open, New …, Back, Cancel); `<button>` does something (a POST form, a script action like Copy). Never `onclick="location.href=…"`. Sizes come only from Pico's form-element variables (app.css sets no button/input padding), so a link-button, a button and an input in one row are the same height; `.small` works on both kinds anywhere (table rows, toolbars); buttons are `width:auto` (Pico makes submits full width). Layout classes, never inline flex: `.actions` (a row of links + POST buttons; its `<form>`s are `display:contents`; `.actions.column` stacks; inside a `<td>`, never `display:flex` on the td itself), `.inline-form` (inputs + one button on a row), `.section-header` (a heading with an action), `.token-line` (a one-line link + Copy). `{% from "_macros.html" import post_button %}` → `post_button(action, label, cls="outline small", confirm=None)`; a confirm is `data-confirm` on the form (app.js), never inline `confirm()`. Look: primary = the form's main submit; `outline` = other actions; `outline secondary` = destructive or back; `small` = table rows and toolbars. `tests/test_templates.py` guards location.href, inline flex and inline confirms. On phones (≤767px) `main table` scrolls sideways itself. Screenshot + alignment recipe: `~/dev/claude/scratch/strata-s3/` (`serve.py` seeds an instance on :5081, `shots.py <dir> <width>` measures every row of controls).
- **Report names** (2026-11-24): the form has Name + Description; the macro name is GENERATED once from the name (`report_service.macro_name_for`: ASCII, lower, `_`; never a DuckDB function/keyword — a macro `range` would shadow `range()` in its own body — nor another report's) and KEPT on rename, because a workbook's Power Query step selects the xlsx sheet (`<macro>`) or table (`<macro>_table`, `stream_service.xlsx_names`; was `StrataReport`) by name. Names are unique per datamodule case-insensitively (checked before the DB's case-sensitive UNIQUE).
- **Report problems** (migration 0014 `report.problem`): `report_service.problem_on(vpath, macro, body, args)` DESCRIBEs a report on a version file (no rows read; defaults bound, a required arg without a default is a typed NULL via `_register_macro(typed=…)`; constraint queries DESCRIBEd too). `_save_report` refuses a report that does not run on the live version (none yet = not checked) and `_report_form` re-renders WHAT WAS TYPED with the error in an `.error-box` (flashes fade after 5 s). After every successful build `report_service.check_reports` re-checks each report (best-effort, after the flip) and `alert_service.reports_broken` mails newly broken ones (not for manual builds; errors via `notify_service.error_html`, so restricted datamodules quote none). The datamodule page marks them `report-broken`.
- **Read audit** (`services/read_audit`, `models/read_log`, migration 0013): one `read_log` row per read of a datamodule's data, by a person or a key, refusals included; no foreign keys (names kept beside ids, so rows outlive what they name). **A route that shows or sends a datamodule's data calls `read_audit.note(kind, dm, report, …)` as soon as it has resolved what is read — BEFORE its access checks, so refusals are recorded — and `read_audit.update(key=…, version=…, run=…, row_count=…)` as it learns more**; one `after_request` writes the row (status, `X-Row-Count`/`Content-Length`, duration, `remote_addr`, User-Agent; 3xx = not a read, nothing written; a write failure is logged, never breaks the response). Kinds (`read_audit.KINDS`): page, data, run, run-data, excel-key, preview, script, source. The query string is kept without `key=`; an unknown token keeps its first 8 characters; a refusal's own short text answer is kept in `detail` (0014; `_refusal_text`: not streamed, ≤ 2000 bytes, not HTML). Pages: `/admin/reads` (+ `.csv`, admins) and `/datamodules/<uuid>/reads` (+ `.csv`, owners, fixed to that datamodule) share `blueprints/reads.py` + `templates/reads/index.html` (keyset paging on id, `read_log.PAGE_SIZE`); each key's "reads" link filters by `key=<id>`. `audit.retention_days` (live, 365, 0 = keep all) pruned in `Worker.sweep` and `reconcile` (`ReconcileReport.expired_reads`). Help page `docs/audit.md`. `api_key.use_count`/`last_used_at` still count successful keyed reads.
- Flash messages auto-dismiss after 5s (`app.js` removes every `.flash` at page load + 5 s) — persistent notices (version banner, token reveal, and `.error-box` for an error that must stay: build error, SQL/report/preview errors) use their own classes, never `.flash`; `tests/test_templates.py` guards it.
- A build that leaves no table or view of its own fails (`datamodule_service._require_something_built`, after the script, before gate checks). Each version's `build_script_snapshot` is shown at `/datamodules/<uuid>/versions/<version uuid>/script`.

## Git Commits
- Do not add "Co-Authored-By" lines to commit messages
